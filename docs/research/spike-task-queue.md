# Эксперимент: очередь фоновых задач

**Статус:** запланирован

## Зачем
Очередь задач — основа обещания надёжности: применение платежей, повтор операций строго по порядку (4.14–4.17), планировщик напоминаний, сверка с панелью, рассылки после перезапуска. Владелец не работал с Procrastinate, поэтому решение принимается после проверки на практике, а не на словах.

## Кандидаты
- **A. Procrastinate** — очередь задач для Python поверх PostgreSQL: блокировки с сохранением порядка, повторы, периодические задачи. Проект ищет дополнительных мейнтейнеров — это риск.
- **B. Своя минимальная очередь** — таблица задач в PostgreSQL и выборка со `SKIP LOCKED`.

В обоих случаях очередь используется только через собственный интерфейс магазина («поставить задачу», «выполнить задачу»), чтобы её можно было заменить, не трогая сценарии.

Redis-очереди (arq, taskiq и т. п.) не рассматриваются: лишний сервис и окно между записью в базу и постановкой задачи, в котором теряются операции.

## Вопросы — одинаковые для обоих кандидатов
1. **Постановка в той же транзакции.** Задача ставится в одной транзакции асинхронной сессии SQLAlchemy с изменением данных; откат отменяет и задачу.
2. **Порядок.** Задачи с одним ключом (идентификатор подписки) выполняются строго по очереди при нескольких воркерах.
3. **Повторы.** Нарастающие интервалы, остановка после заданного времени, задача становится видимой как проваленная.
4. **Периодическая задача** раз в минуту не выполняется дважды при двух воркерах.
5. **Падение воркера посреди задачи** — задача не теряется и выполняется снова.
6. **Наблюдаемость** — как увидеть зависшие и проваленные задачи (нужно для «Требуют внимания»).
7. **Понятность кода** — насколько легко владельцу читать код каждого варианта.

## Как проводить
- Отдельная папка вне репозитория проекта, Claude Code.
- PostgreSQL в Docker.
- Для каждого вопроса — небольшой сценарий, который можно запустить и увидеть результат.
- Код после эксперимента не переносится в проект.
