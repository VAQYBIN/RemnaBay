# Поведение панели Remnawave

Факты, на которые опирается спека. Проверено по исходникам бэкенда (github.com/remnawave/backend, коммит от 2026-09-12) и на живой панели.

## SDK для Python
- **remnawave/python-sdk** (пакет `remnawave`) — **в архиве, не поддерживается**; документация Remnawave советует альтернативные SDK сообщества или работу с API напрямую.
- **sm1ky/remnawave-api** (пакет `remnawave-api`) — живое продолжение того же SDK: Pydantic-модели, поддерживает sm1ky. На 2026-10-03 таблица совместимости: контракт 3.4.5 — панель от 3.4.4, контракт 3.4.3 — панель от 3.4.0. Используется магазином — [решение 0028](../decisions/0028-panel-client.md).

## Сброс трафика
- **Не сбрасывать** — счётчик не обнуляется.
- **Раз в день** — каждую ночь по времени сервера панели.
- **Раз в неделю** — по понедельникам.
- **Раз в месяц** — первого числа календарного месяца, у всех одновременно.
- **Раз в месяц (от даты создания)** — в день месяца, соответствующий дате создания пользователя. Если такого числа в месяце нет — в последний день месяца. Первый сброс — не раньше чем через месяц после создания.
- Дату создания можно передать только при создании пользователя; изменить её через API нельзя.
- Дату следующего сброса API пользователя не отдаёт; её нужно вычислять по стратегии и дате создания.
- Массовое действие «сбросить трафик всем» обнуляет счётчик у всех пользователей, включая тех, у кого стратегия «не сбрасывать».

## Статусы
- При исчерпании трафика пользователь получает статус LIMITED, панель отправляет вебхук.
- При повышении лимита пользователь сразу возвращается в ACTIVE, дополнительных действий не нужно. *(проверено на живой панели)*

## Устройства (HWID)
- При включённом лимите устройств панель отправляет вебхуки `user_hwid_devices.added` и `user_hwid_devices.deleted` с данными пользователя и устройства. При выключенном — не отправляет.
- Список всех устройств в API есть, но его фильтры рассчитаны на фронтенд и дорогие для БД. Поэтому магазин ведёт собственный реестр устройств по вебхукам, а не ищет по панели.
- Список устройств одного пользователя — обычный запрос; им пользуется сверка реестра для триальных подписок (5.8).
- Отзыв подписки в панели (`user.revoked`) меняет ссылку подписки.
- По словам автора, почти все операторы используют лимит устройств.

## События пользователя (вебхуки)
- Всегда: `user.created`, `user.modified`, `user.deleted`, `user.revoked`, `user.disabled`, `user.enabled`, `user.limited`, `user.expired`, `user.traffic_reset`, `user.first_connected`.
- `user.bandwidth_usage_threshold_reached` — при достижении порогов расхода трафика, настроенных в панели.
- `user.expiration` и `user.not_connected` — только если включены соответствующие параметры в `.env` панели. Поэтому магазин не опирается на них и ведёт напоминания об истечении сам.

## Подпись вебхуков
- Панель подписывает вебхуки: заголовки `X-Remnawave-Signature` и `X-Remnawave-Timestamp`. Магазин проверяет подпись и отклоняет неподписанные события.

## Уведомления об истечении в панели
- Включаются в `.env` панели: `EXPIRATION_NOTIFICATIONS_ENABLED` и `EXPIRATION_NOTIFICATIONS` — список смещений в часах от −744 до 744, не больше пяти до истечения и пяти после.
- Раз в минуту панель ищет пользователей, у которых дата окончания со смещением попадает ровно в текущую минуту, и отправляет `user.expiration` со смещением в данных события.
- Пропущенная минута (панель перезапускалась) не восстанавливается.

## Доставка вебхуков
- Панель повторяет неудавшуюся отправку вебхука 3 раза с интервалом 5 секунд, после чего событие отбрасывается. Если магазин недоступен дольше ~15 секунд, событие теряется. Поэтому магазин не должен полагаться на то, что получит каждое событие, и периодически сверяется с панелью.

## Конфиги Subscription Page
- Конфиги страницы подписки хранятся в панели; их может быть несколько, с тегами и порядком; есть конфиг по умолчанию.
- API: `GET /api/subscription-page-configs` — список, `GET /api/subscription-page-configs/{uuid}` — конфиг целиком.
- Какой конфиг у пользователя: поле `subpageConfigUuid` внешнего сквада; без внешнего сквада — конфиг по умолчанию.
- Запрос `GET /api/subscriptions/subpage-config/{shortUuid}` (тело `{"requestHeaders": {...}}`, скоуп `subscriptions:subpage-config`) возвращает `subpageConfigUuid` и `webpageAllowed`. `subpageConfigUuid = null`, если у пользователя нет внешнего сквада, у сквада не задан конфиг или пользователь не найден. *(проверено на живой панели, 3.4.4)*
- Конфиг по умолчанию — uuid `00000000-0000-0000-0000-000000000000`, имя `Default`; удалить нельзя, изменить можно. Подставляет его приложение Subscription Page, а не панель; переменная `SUBPAGE_CONFIG_UUID` приложения навязывает один конфиг всем.
- Приложение Subscription Page (8.0.0) читает конфиги один раз при старте.
- Подробности — [spike-panel.md](spike-panel.md), вопрос 1.
- Содержимое конфига (версия «1»), проверяется панелью по строгой схеме:
  - `locales` — языки; все тексты хранятся как «язык → текст»;
  - `platforms` — ios, android, windows, macos, linux, androidTV, appleTV; у платформы — название и список приложений;
  - у приложения — название, признак рекомендуемого (`featured`) и шаги-блоки (заголовок, описание, кнопки);
  - кнопки трёх типов: `external` (внешняя ссылка), `subscriptionLink` (импорт в приложение по диплинку с подстановкой `{{SUBSCRIPTION_LINK}}`, `{{USERNAME}}`), `copyButton` (копирование ссылки);
  - `brandingSettings`, `svgLibrary`, `uiConfig` — для веб-страницы.
- В конфиге по умолчанию — приложения Happ, Stash, Shadowrocket, Streisand, FlClashX, Koala Clash, Prizrak-Box и другие.

## Идентификация
- Telegram ID у пользователя необязателен и не уникален: у нескольких пользователей может быть один Telegram ID.
- В панели v3 (3.4.4) у пользователя **нет поля `uuid`**. Пользователь адресуется числовым `id`; уникальны также `shortUuid` и `username`. `POST /api/users/resolve` переводит любой из трёх в остальные. Ссылка подписки — `https://{SUB_PUBLIC_DOMAIN}/{shortUuid}`. *(проверено на живой панели)*

## Правила ответов (выдача подписки)
- Правила проверяются по порядку, срабатывает первое совпавшее; без совпадений — 403. Условия — только по заголовкам запроса.
- Браузеру страницу показывает приложение Subscription Page, если правила для его заголовков дают `BROWSER`. Иначе приложение рвёт соединение, и клиент видит ошибку обратного прокси (у владельца — «502 Bad Gateway» nginx). *(проверено на живой связке и в Telegram)*
- Подробности — [spike-panel.md](spike-panel.md), вопрос 2.

## API-токены
- Права токена — скоупы: `*`, `<раздел>:*`, `<раздел>:read|write` или отдельный запрос `<раздел>:<действие>`. По умолчанию — `*`.
- В запись разделов входят массовые действия над всеми пользователями (`users:bulk-all-*`, `external-squads:add-users`).
- Разделы API-токенов, passkey, настроек Remnawave и SSH нод токену недоступны.

## Дата окончания
- Дата окончания обязательна.
- Клиентские приложения показывают подписку с датой окончания в 2099 году как «бессрочную». Ориентир — именно 2099 год. *(со слов автора, по опыту)*
