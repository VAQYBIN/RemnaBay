# 0049. Подготовка этапа 4: документация API, поток уведомлений, смена ключа шифрования

- **Дата:** 2026-10-06
- **Статус:** принято

## Контекст
Перед этапом 4 ([plan.md](../plan.md), блок 1) в [open-questions.md](../open-questions.md) оставались вопросы, без ответа на которые нельзя спроектировать вход, пути и настройки: открыта ли документация API в рабочем режиме, что делать с потоком уведомлений при массовом провале операций, что видит команда после смены ключа шифрования.

## Решение
- **Документация API (`/docs`, `/redoc`, `/openapi.json`)** в рабочем режиме закрыта, при разработке доступна. Схему для генерации клиента админки берут при сборке, а не с работающего магазина.
- **Уведомления о проваленных операциях** (4.31) — не чаще одного «Операция не выполнена» в 10 минут; в тексте — сколько операций ждут разбора.
- **Смена или потеря `ENCRYPTION_KEY`:** магазин запускается; способ оплаты, ключи которого не расшифровываются, недоступен для выбора клиентом; в админке он помечен «Ключи нужно ввести заново», пункт чек-листа «Способ оплаты» снова не выполнен; ошибка расшифровки — в журнале.

## Альтернативы
- Документация API открыта всегда — отклонено: схема API видна всем, кто откроет адрес магазина.
- Уведомлять о каждой проваленной операции — отклонено: при массовом сбое (например, панель после обновления отвечает 500 на каждый запрос) уведомлений столько же, сколько операций.
- Не запускать магазин, если секреты не расшифровываются, — отклонено: подписки, сверка и уже оплаченные платежи продолжают работать, страдает только приём новых оплат этим способом.

## Последствия
- Этап 4 определяет, как магазин отличает рабочий режим от разработки (параметр — в `.env.example` с пояснением).
- Текст `team.operation_failed` получит переменную с числом ждущих операций — правка текста в [03-bot-texts.md](../03-bot-texts.md) на утверждение владельцу вместе с этапом 4.
- Поведение при нерасшифровываемых ключах провайдеров реализуют блоки 1 (пометка, чек-лист) и 3 (способ оплаты недоступен).
- Вопросы «Документация API в рабочем режиме», «Много проваленных операций сразу — много уведомлений» и «Секреты после смены ключа шифрования» закрыты.
