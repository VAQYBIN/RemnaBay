# 0051. Вход и главная: уточнения этапа 4

- **Дата:** 2026-10-06
- **Статус:** принято

## Контекст
При разбивке этапа 4 ([plan.md](../plan.md), блок 1) остались места, которые спека не определяла: чем показывать знак RemnaBay, которого ещё нет; какую версию панели считать совместимой (1.8); где хранить логотипы оператора; что считать активной подпиской на главной (1.17). Кроме того, этапу нужны технические решения, которые влияют на развёртывание и безопасность: как магазин отличает рабочий режим от разработки ([решение 0049](0049-stage-4-preparation.md)), пути на одном домене ([решение 0026](0026-deployment.md)), механика входа через Telegram (1.4–1.6).

## Решение

### Ответы владельца
- **Знак RemnaBay** — временная заглушка: плитка цвета `#1FA4A0` с буквой «R». Один SVG-файл в админке, помечен как временный; когда появится настоящий знак, заменяется только этот файл.
- **Совместимая версия панели (1.8)** — та же мажорная и минорная версия, что у поддерживаемой (`SUPPORTED_PANEL_VERSIONS`), и патч не ниже: сейчас 3.4.x начиная с 3.4.4. Исправления панели не роняют пункт чек-листа; новая минорная версия (3.5) становится совместимой только после контрактного теста. При несовместимой версии чек-лист показывает требуемую.
- **Логотипы оператора** хранятся в PostgreSQL. Отдаются по адресу с хэшем содержимого, браузер кэширует файл до смены логотипа.
- **Активная подписка (1.17)** — не удалена и дата окончания в будущем, независимо от статуса в панели. Отключённая в панели и с исчерпанным трафиком тоже считаются: срок у них оплачен.

### Режим работы
- Параметр `.env` `DEV_MODE` — необязательный, по умолчанию `false` (рабочий режим). Оператор его не задаёт.
- В режиме разработки: открыта документация API (`/docs`, `/redoc`, `/openapi.json`); бот получает обновления опросом, а не вебхуком; cookie сессии без признака `Secure`, чтобы работал `http://localhost`.

### Пути на одном домене
| Путь | Что |
|---|---|
| `/admin/…` | Админка |
| `/api/admin/…` | API админки |
| `/webhooks/telegram` | Вебхук бота |
| `/webhooks/panel` | Вебхук панели |
| `/brand/…` | Логотипы оператора: публичные, нужны экрану входа и странице-переходнику |
| `/health` | Проверка здоровья |

Корень `/` свободен — под будущий клиентский сайт ([решение 0003](0003-core-and-channels.md)).

### Бот
- Бот работает в роли «веб». В рабочем режиме при старте магазин сам регистрирует вебхук Telegram с секретом; секрет генерируется магазином и хранится в базе зашифрованным, как секрет вебхука панели.

### Вход через Telegram
- **По кнопке на странице входа:** браузер создаёт запрос входа и получает ссылку на бот (`t.me/<бот>?start=login_…`) и короткий код. Бот присылает участнику команды подтверждение с тем же кодом. После нажатия «Подтвердить вход» браузер получает сессию; запрос одноразовый и действует ограниченное время (1.5). Аккаунту не из команды бот отвечает как на непонятное сообщение, а страница входа показывает отказ (1.6).
- **Зачем код:** без него злоумышленник мог бы прислать владельцу свою ссылку входа; владелец подтвердил бы вход, а сессию получил бы браузер злоумышленника. Код на странице и в боте должен совпасть — бот просит подтверждать, только если коды одинаковые.
- **По команде `/admin`:** бот присылает кнопку `login_url`; Telegram добавляет к адресу подписанные данные аккаунта. Магазин проверяет подпись токеном бота, свежесть данных (не старше срока подтверждения входа) и то, что эти данные не использовались. Для этой кнопки оператор указывает домен магазина у @BotFather (`/setdomain`) — шаг попадает в документацию оператора (этап 11).
- **Сессия** — случайный токен в cookie `HttpOnly`, `SameSite=Lax`; в базе хранится только хэш. Отзыв доступа завершает сессию на следующем же запросе. Изменяющие запросы принимаются только со страниц самого магазина (проверка `Origin`).

### Клиент админки
- Схема API выгружается командой `remnabay openapi` без запуска сервера. Сгенерированные типы лежат в репозитории (`admin/src/api/schema.d.ts`), чтобы образ собирался без Python; CI перегенерирует их и падает, если бэкенд и админка разошлись ([решения 0049](0049-stage-4-preparation.md), [0050](0050-admin-api-client.md)).
- `openapi-typescript` печатает типы через API компилятора TypeScript 5, а у TypeScript 7, на котором написана админка, такого API нет (в пакете только нативный компилятор). Поэтому генератор живёт в отдельном пакете `admin/tools/openapi-typescript` со своим lock-файлом: `openapi-typescript` и `typescript` 5 — только для генерации, в сборку админки не входят. Скрипт — `scripts/admin-codegen.sh`.
- Тем же скриптом из бэкенда берутся токены бренда RemnaBay по умолчанию (`admin/src/styles/default-brand.css`): админка показывает их до ответа сервера, чтобы экран не мигал.

### Логотипы
- Загрузка — телом запроса с типом файла, без форм (не нужна зависимость для разбора форм).
- Проверки: PNG — квадрат не меньше 512×512; SVG — квадратная область `viewBox`; размер файла — до 1 МБ. SVG отдаётся с запретом скриптов (CSP `sandbox`).

### Шкала цвета
- Шкала, контраст и предупреждение о близости к смысловому цвету (1.24) считаются на сервере, в пространстве OKLCH, без сторонних библиотек. Админка получает готовые значения; позже их же использует страница-переходник (блок 12).

## Альтернативы
- **Знак RemnaBay:** подождать настоящий знак — отклонено, этап остановился бы на 1.23 и 1.26; только название текстом — отклонено, раме нужна плитка знака в шапке.
- **Совместимость панели:** только точный список версий — отклонено, любое исправление панели требовало бы новой версии магазина; «не ниже минимальной» — отклонено, несовместимость API обнаружилась бы уже в работе.
- **Логотипы на томе Docker** — отклонено: вторая вещь для резервной копии и переезда, проблемы с правами на томе (магазин работает не от root), база и файлы могут разойтись при восстановлении. Решение пересматривается, если магазину понадобится хранить много крупных файлов.
- **Активная подписка — только со статусом «активна» в панели** — отклонено: отключённая или исчерпавшая трафик подписка всё равно оплачена.
- **Вход только по `login_url`** — отклонено: критерий 1.4 требует входа и по кнопке на странице входа.
- **Вход без кода** — отклонено: см. «Зачем код».
- **Сгенерированные типы не в репозитории, сборка админки берёт схему у Python** — отклонено: этапу сборки админки в Docker понадобился бы Python и все зависимости бэкенда.
- **Шкала цвета в браузере** — отклонено: странице-переходнику (блок 12) нужны те же токены без JavaScript админки.
