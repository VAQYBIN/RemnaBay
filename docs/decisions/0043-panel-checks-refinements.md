# 0043. Уточнения спеки по итогам проверок на панели

- **Дата:** 2026-10-04
- **Статус:** принято

## Контекст
Проверки этапа 1 на панели 3.4.4 и Subscription Page 8.0.0 ([research/spike-panel.md](../research/spike-panel.md)) показали три места, где спека расходится с поведением панели:
- если правила ответов панели не пускают браузер на страницу подписки, Subscription Page рвёт соединение, и клиент по кнопке «Открыть в браузере» видит ошибку обратного прокси (у владельца — «502 Bad Gateway» nginx). Текст `guide.unavailable` при этом советует открыть ссылку в браузере;
- конфиг по умолчанию в 12.1 не был назван, а веб-страница подписки может показать не тот конфиг, что бот;
- в формате миграции пользователь панели определялся по UUID, а в панели v3 этого поля у пользователя нет.

## Решение
1. **«Открыть в браузере» только когда браузер пустят.** Вместе с конфигом Subscription Page магазин узнаёт у панели, пускает ли она браузер на страницу подписки (запрос `subpage-config` с типичными заголовками браузера, поле `webpageAllowed`). Если нет — кнопки «Открыть в браузере» в инструкции нет, вместо `guide.unavailable` — `guide.unavailable_no_browser` без совета открыть браузер, а в админке на экране «Панель» — предупреждение. Критерии 12.6, 12.8, 12.16, 12.17.
2. **Конфиг по умолчанию назван явно.** Если у пользователя нет внешнего сквада или у сквада нет конфига, инструкция берётся из конфига по умолчанию с uuid `00000000-0000-0000-0000-000000000000` (12.1).
3. **Пользователь панели в формате миграции** — числовой ID, `shortUuid` или `username`; хватает любого одного ([migration-format.md](../migration-format.md)).

## Альтернативы
- Оставить кнопку «Открыть в браузере» всегда и только описать проблему в документации оператора — отклонено: клиент получает голую ошибку, а бот сам отправляет его туда.

## Последствия
- Ответ панели — приближение: правила могут различать браузеры по User-Agent, и конкретный браузер клиента может получить другой ответ, чем «типичный браузер» магазина.
- В документацию для операторов (этап 11) входят два предупреждения:
  - переменная `SUBPAGE_CONFIG_UUID` в Subscription Page показывает всем один конфиг на веб-странице; бот её не видит и берёт конфиг по внешнему скваду — инструкции в боте и на странице разойдутся;
  - Subscription Page читает конфиги только при запуске: после правки конфига в панели бот обновится сам (12.7), а веб-страница — только после перезапуска Subscription Page.
