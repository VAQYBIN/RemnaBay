# 0042. Свой тонкий клиент панели вместо SDK

- **Дата:** 2026-10-04
- **Статус:** принято

## Контекст
[Решение 0028](0028-panel-client.md) выбрало SDK `remnawave-api` за собственным интерфейсом магазина и требовало при старте кода проверить совместимость зависимостей SDK со стеком: несовместимость — повод сразу перейти на свой клиент за тем же интерфейсом.

Проверка на этапе 1 ([research/spike-panel.md](../research/spike-panel.md), вопрос 4):
- SDK держит `httpx<0.28` через жёсткую привязку к внутренностям `rapid-api-client==0.6.0` (2024 год) и без переписывания обновиться не может. Стек работает только с двумя HTTP-библиотеками: httpx 0.27 для SDK и httpx2 для тестов FastAPI. httpx 0.27 исправлений больше не получает.
- Пробелы SDK для магазина: через него нельзя обнулить поле (проверено на панели), сетевые ошибки выходят наружу необработанными, новое значение перечисления в ответе ломает разбор, под pyright strict каждый вызов требует `cast`. Модель конфига Subscription Page в SDK не описана.
- Магазину в MVP нужно 16 запросов к панели и проверка подписи вебхуков.

## Решение
- Магазин работает с панелью через **свой тонкий клиент** на httpx2 за интерфейсом «клиент панели» из решения 0028. Остальной код по-прежнему не знает, что внутри.
- SDK `remnawave-api` не используется и убирается из зависимостей.
- Модели запросов и ответов — Pydantic, только для нужных магазину запросов; пишутся вручную со сверкой по контракту панели поддерживаемых версий (`libs/contract` бэкенда Remnawave).
- Клиент делается на этапе 2 вместе с интерфейсом и контрактным тестом.

## Альтернативы
- Оставить SDK с обходным путём (httpx 0.27 рядом с httpx2) — отклонено: два HTTP-стека, неподдерживаемый httpx, пробелы SDK пришлось бы закрывать в обёртке.
- Подменить httpx для SDK через `override-dependencies` uv или `httpx2.alias_httpx()` — отклонено: скрывает заявленное ограничение SDK, хрупко и не закрывает пробелы SDK.

## Последствия
- Решение 0028 заменено этим решением; интерфейс «клиент панели» и правило «остальной код не знает о внутренностях» сохраняются.
- Контрактный тест ([решение 0027](0027-versions.md)) проверяет вызовы и модели клиента по `openapi.json` каждой поддерживаемой версии панели (файл есть в образе `remnawave/backend:<версия>`), а не таблицу совместимости SDK.
- Новая версия панели — сверить модели клиента с её контрактом, прогнать контрактный тест, затем расширить диапазон.
- Сопровождение моделей — на магазине.
- Модели клиента терпят новые значения перечислений и умеют отправлять `null` для полей, которые панель позволяет обнулить.
