# 0044. Rich-сообщения и даты по итогам проверок в Telegram

- **Дата:** 2026-10-04
- **Статус:** принято

## Контекст
Проверки этапа 1 в клиентах Telegram ([research/spike-telegram.md](../research/spike-telegram.md)):
- Telegram Web K вместо rich-сообщений с рядами кнопок и обычных сообщений с неактивной кнопкой показывает заглушку «не поддерживается»; Desktop, Android и Web A показывают их полностью;
- сущность date_time в обычных сообщениях все проверенные клиенты показывают в местном часовом поясе клиента, но Android внутри rich-сообщений показывает запасной текст бота (местное время — только по нажатию); старые версии клиентов, вероятно, тоже показывают запасной текст;
- часовой пояс пользователя Telegram боту не сообщает.

## Решение
1. **Кнопки внутри rich-экранов остаются** ([решение 0017](0017-bot-format.md)): выбор тарифа и карточка подписки — как задумано. На Web K магазин не ориентируется.
2. **Неактивные кнопки остаются** (0017).
3. **Запасной текст даты** — дата и время в часовом поясе магазина (настройка, по умолчанию Москва) с подписью пояса: «1 ноября 2026, 23:00 (МСК)». Подпись — «МСК», а не «UTC+3»: так понятнее клиентам. Текст задаётся ключом `date.fallback` ([03-bot-texts.md](../03-bot-texts.md)).

## Альтернативы
- Кнопки действий rich-экранов — под сообщением, без неактивных кнопок, ради Web K — отклонено.
- Запасной текст — только дата без времени — отклонено: у клиента в другом поясе дата может разойтись на день.
- Карточка подписки обычным сообщением, чтобы Android показывал местное время, — отклонено: карточка теряет структуру.

## Последствия
- Клиенты Web K и старых версий видят заглушку вместо части экранов; бот повлиять на это не может — у rich-сообщений нет запасного текста.
- Клиент, у которого приложение не форматирует дату, видит время магазина с подписью пояса и пересчитывает сам; Android по нажатию показывает местное время.
- Даты в админке — по-прежнему в часовом поясе магазина (1.18).
