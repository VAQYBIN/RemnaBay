# 0013. Защита триала слоями

- **Дата:** 2026-10-01
- **Статус:** принято

## Контекст
Злоупотребление триалом через новые Telegram-аккаунты — распространённая проблема у операторов; сообщество даже ведёт общие чёрные списки Telegram ID. Полностью предотвратить мультиаккаунты нельзя: аккаунт стоит почти ничего.

## Решение
Цель — чтобы злоупотребление обходилось дороже покупки, а ущерб от него был маленьким. Слои:
1. **Ограничение ущерба** (всегда): короткий срок, малый трафик, одно устройство, при желании отдельный сквад.
2. **Проверки на входе:** один триал на клиента; чёрный список Telegram ID — собственный и подключаемые внешние; необязательная проверка подписки на канал.
3. **Проверка по устройству после выдачи** — основная защита: магазин ведёт реестр устройств по вебхукам панели, и триал отзывается, если устройство уже встречалось у другого клиента.
4. **Точка расширения** «проверка перед выдачей триала» для всего остального.

Отзыв триала — не блокировка: клиент может сразу купить подписку. Чёрный список действует только на триал.

## Альтернативы
- Только «один триал на клиента» — отклонено: не защищает от мультиаккаунтов.
- Подтверждение номера телефона — отклонено: каждый Telegram-аккаунт и так привязан к уникальному номеру, поэтому проверка ничего не добавляет; при этом отпугивает аудиторию, ценящую приватность, и создаёт у оператора обязанности по хранению персональных данных.
- Эвристики по возрасту аккаунта в ядре — отклонено: неточные, дают ложные срабатывания; допустимы как расширение.

## Последствия
- Защита по устройству работает только при включённом в панели лимите устройств; админка предупреждает, если он выключен.
- Магазин хранит реестр устройств клиентов.
