# 0048. Надёжность: уточнения этапа 3

- **Дата:** 2026-10-05
- **Статус:** принято

## Контекст
При реализации этапа 3 ([plan.md](../plan.md), блок 4) остались места, которые спека не определяла: тексты уведомлений команде, задержка сообщения 4.19, уведомление о конце простоя панели, действующее лицо в журнале для вебхука с неверной подписью, состояние «решена вручную» у операции очереди.

## Решение
- **Тексты уведомлений команде** — ключи `team.*` в [03-bot-texts.md](../03-bot-texts.md), раздел «Уведомления команде»; формулировки утверждены владельцем.
- **Сообщение «Оплата получена, подписка создаётся» (4.19)** — если через 10 секунд после подтверждения оплаты платёж ещё не применён.
- **Конец простоя панели:** если о простое уведомляли (4.13), команда получает уведомление о его конце с началом и концом простоя. Короткий простой без уведомления заканчивается тихо — только запись в журнале.
- **Вебхук с неверной подписью** записывается в журнал от имени системы: отправитель не подтверждён.
- **Операция очереди** получает состояние «решена вручную» — его вводит 4.31; описание в [01-domain.md](../01-domain.md) дополнено.

## Альтернативы
- Строки уведомлений команде в коде — отклонено: оператор не смог бы их переписать и перевести.
- Уведомлять о конце любого простоя — отклонено: после короткого простоя без уведомления сообщение о его конце было бы непонятным шумом.
- Записывать отклонённый вебхук от имени панели — отклонено: без верной подписи нельзя утверждать, что его прислала панель.

## Последствия
- Вопросы «Через сколько клиенту писать «Оплата получена…» (4.19)» и «Уведомление «панель снова доступна»» в [open-questions.md](../open-questions.md) закрыты.
- Текст `team.panel_available_again` утверждён владельцем вместе с остальными.
