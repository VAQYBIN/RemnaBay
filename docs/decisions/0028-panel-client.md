# 0028. Клиент панели: SDK remnawave-api за собственным интерфейсом

- **Дата:** 2026-10-03
- **Статус:** заменено решением [0042](0042-own-panel-client.md)

## Контекст
Официальный Python SDK (remnawave/python-sdk) в архиве. Его живое продолжение — `remnawave-api` от sm1ky, следует за версиями панели (контракт 3.4.5 для панели от 3.4.4). Альтернатива — свой тонкий клиент по официальной OpenAPI-спеке панели, как в remnawave-tg-shop автора.

## Решение
- Магазин работает с панелью через SDK `remnawave-api`.
- SDK используется **только через собственный интерфейс магазина** («клиент панели»); остальной код не знает о SDK.
- Версия SDK закреплена lock-файлом и обновляется только вместе с расширением диапазона поддерживаемых версий панели, после тестов.
- Контрактный тест проверяет совместимость версии SDK с поддерживаемыми версиями панели и наличие используемых вызовов в их OpenAPI-спеке.
- При старте кода проверяется совместимость зависимостей SDK с остальным стеком. Несовместимость — повод сразу перейти на свой клиент за тем же интерфейсом.

## Альтернативы
- Свой тонкий клиент по OpenAPI-спеке — отложено как запасной вариант. Плюсы: только нужные ~15 эндпоинтов, никаких чужих зависимостей, опыт автора. Минусы: поддержка на нас; меньше готового.
- Архивный remnawave/python-sdk — отклонено: не поддерживается.

## Плюсы и риски
- Плюс: готовые модели всех эндпоинтов — меньше мест, где агент может ошибиться в формате запроса.
- Риск: один мейнтейнер. Закрывается интерфейсом магазина: замена на свой клиент затрагивает одно место.
