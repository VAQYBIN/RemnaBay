# 0006. Несколько подписок у клиента

- **Дата:** 2026-09-30
- **Статус:** принято

## Контекст
Обычно клиенту нужна одна подписка, но встречаются клиенты, которым нужно несколько и которые хотят сами ими управлять.

## Решение
Клиент — тот, кто платит и управляет; подписок у него может быть несколько, каждая — отдельный пользователь панели со своим тарифом. Главное правило: простой случай не должен платить за сложный — пока подписка одна, интерфейс не показывает выбора. Лимит подписок на клиента задаёт оператор. Подписки именуются клиентом. Триал и реферальные связи принадлежат клиенту.

## Альтернативы
- Одна подписка на клиента — отклонено: не покрывает реальный запрос.
- Отдельный аккаунт на каждую подписку — отклонено: клиент не может управлять ими из одного места.

## Последствия
- Покупка новой подписки и продление — разные сценарии.
- При миграции несколько пользователей панели с одним Telegram ID становятся одним клиентом.
- Передача подписки и делегирование доступа не входят в MVP.
