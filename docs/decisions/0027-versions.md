# 0027. Версии и правила обновления

- **Дата:** 2026-10-03
- **Статус:** принято

## Контекст
Агенту нужны конкретные версии, иначе он выберет их сам. Важнее номеров — правила, по которым версии живут дальше, и совместимость с панелью Remnawave.

## Инструменты
- **uv** — зависимости и lock-файл Python.
- **ruff** — линтер и форматирование.
- **pyright** в строгом режиме — проверка типов (решение 0022).
- **pytest** — тесты.
- **npm** — зависимости и lock-файл фронтенда.

## Правила
- **Lock-файлы в репозитории.** Образ собирается строго по ним; одинаковый код даёт одинаковую сборку.
- **Обновления зависимостей — регулярно и небольшими шагами:** автоматические предложения обновлений; каждое проходит проверку типов и тесты.
- **Python:** переход на следующую версию — после второй исправительной версии и готовности всех зависимостей (для 3.15 — ориентировочно начало 2027 года).
- **Совместимость с панелью:**
  - поддерживаемый диапазон версий панели указан в README и проверяется при подключении (1.8);
  - **контрактный тест** проверяет, что вызовы и модели клиента панели соответствуют OpenAPI-спеке каждой поддерживаемой версии панели (практика из remnawave-tg-shop автора; уточнено [решением 0042](0042-own-panel-client.md));
  - новая версия панели: прогнать контрактный тест и проверить сценарии, затем расширить диапазон.
- **Bot API:** aiogram обновляется, когда нужны новые возможности Telegram или выходит исправление.
- **Версии магазина:** семантическое версионирование и changelog к каждой версии.

## Последствия
- Точные номера фиксируются lock-файлами при начале кода; это решение задаёт базу и правила.
