# 0067. Сообщение о возврате без смены срока и отмена действий команды

- **Дата:** 2026-10-15
- **Статус:** принято

## Контекст
При реализации блока 10 (этап 9) появились два вопроса, на которые спека не отвечала:
- **Возврат, который не меняет срок.** С11 «Возврат выполнен» говорит «Подписка теперь действует до {end_date}», С12 «Мы разобрались с вашим платежом: деньги возвращены» о подписке молчит. Какое из них отправлять, если магазин срок не трогает: платёж «решён вручную» (срок применяла команда) или платёж, оплаченный период которого уже прошёл.
- **Отмена операции, которую начала команда.** По 4.32 после отмены проваленной операции клиент получает «Не удалось выполнить действие, напишите в поддержку» (С17). Но выдачу дней (10.3) и сброс устройств из карточки клиента (10.5) начинает команда: клиент может не знать о подарке и получил бы непонятную ошибку.

## Решение
- **Возврат без смены срока:** если у платежа есть подписка, которую видит клиент, — С11 с её текущей датой окончания (`event.refunded.ended`, если подписка уже закончилась); если подписки нет — С12 `event.payment_resolved.refunded`. Возврат неприменённого и неизвестного платежа (10.14) — всегда С12: клиент ждал применения, и «мы разобрались» отвечает именно на это.
- **Отмена действия команды — без сообщения клиенту.** Если команда отменила проваленную операцию, которую начала сама (выдача дней, сброс устройств из карточки клиента), клиент ничего не получает: о сбое знает только команда — по журналу и карточке клиента. С17 остаётся для действий клиента: покупка, триал, промокод на дни, удаление устройства в боте.

## Альтернативы
- Отправлять С17 при любой отмене, как было в 4.32, — клиент получает ошибку за действие, которого не совершал.
- При возврате без смены срока всегда отправлять С12 — клиент с подпиской не узнаёт, что подписка продолжает действовать.

## Последствия
- Критерий 4.32 уточнён: С17 — только для операций, которые начал клиент.
- В С17 (03-bot-texts) указано, когда сообщение не отправляется.
