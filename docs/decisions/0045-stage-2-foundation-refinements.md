# 0045. Фундамент: права токена панели, контракт панели, очистка очереди

- **Дата:** 2026-10-05
- **Статус:** принято

## Контекст
При разбивке этапа 2 ([plan.md](../plan.md)) остались три вопроса, без которых часть задач не начать:
- **Права API-токена магазина.** В панели 3.4.4 токен по умолчанию получает скоуп `*` — доступ ко всему API, включая массовые действия над всеми пользователями. Вопрос был записан в [open-questions.md](../open-questions.md) к этапу 2.
- **Где брать OpenAPI панели для контрактного теста** ([решение 0042](0042-own-panel-client.md)). Файл `openapi.json` лежит в образе `remnawave/backend:<версия>`; лицензия бэкенда панели — AGPL-3.0.
- **Сколько хранить выполненные задачи очереди.** [Решение 0024](0024-task-queue.md) требует очистки, но срок не задан.

## Решение
- **Права токена.** В MVP магазин не проверяет права токена при подключении (1.8). Клиент панели хранит, какое право нужно каждому его запросу; список минимальных прав попадает в документацию оператора (этап 11). Сейчас это 15 прав: `hwid-user-devices:delete`, `hwid-user-devices:delete-all`, `hwid-user-devices:list-by-user`, `internal-squads:list`, `subscription-page-configs:get`, `subscription-settings:get`, `subscriptions:subpage-config`, `system:metadata`, `users:by-id`, `users:by-username`, `users:create`, `users:list`, `users:reset-traffic`, `users:resolve`, `users:update`.
- **OpenAPI панели — не в репозитории.** Скрипт `scripts/fetch-panel-openapi.sh` достаёт файл из образа панели каждой поддерживаемой версии; CI делает это перед тестами. Без файла контрактный тест падает с подсказкой, а не пропускается.
- **Очистка очереди.** Выполненные и отменённые задачи хранятся 30 дней (постоянная в коде, без настройки в админке). Проваленные и ждущие не удаляются, пока их не разберут. Попытки остаются в журнале и после очистки.

## Альтернативы
- Проверять права токена при подключении — отложено: требует отдельной проверки и не нужно для переезда автора.
- Ничего не делать с правами в MVP — отклонено: оператору нужен короткий путь к безопасной настройке.
- Положить `openapi.json` в репозиторий — отклонено: тест работал бы без Docker, но AGPL-файл в MIT-репозитории требует отдельного разбора лицензии.
- Хранить задачи 7 или 90 дней — выбрано 30: хватает, чтобы разобрать недавний случай по самой задаче, дальше история — в журнале.

## Последствия
- Вопрос «Права API-токена магазина» в [open-questions.md](../open-questions.md) закрыт.
- Новая версия панели в диапазоне поддержки — добавить её в `SUPPORTED_PANEL_VERSIONS` (`src/remnabay/panel/__init__.py`), получить её OpenAPI скриптом и прогнать контрактный тест.
- Попутно при сверке с кодом панели 3.4.4:
  - подпись вебхука — HMAC-SHA256 тела секретом, в hex; заголовок `X-Remnawave-Timestamp` в подпись не входит и от повтора не защищает, однократность (4.2) обеспечивает магазин;
  - панель рвёт соединение без заголовков `X-Forwarded-For` и `X-Forwarded-Proto: https`; клиент магазина добавляет их сам, если адрес панели — `http://` во внутренней Docker-сети;
  - стратегия `MONTH_ROLLING` — сброс раз в месяц в день создания пользователя, то есть «раз в месяц от даты создания» ([решение 0010](0010-traffic-reset.md)).
