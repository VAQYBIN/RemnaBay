# 0014. Напоминания планирует магазин

- **Дата:** 2026-10-01
- **Статус:** принято

## Контекст
В панели есть уведомления об истечении: смещения задаются в её `.env`, раз в минуту панель ищет пользователей, чья дата окончания со смещением попадает ровно в текущую минуту, и шлёт вебхук. Вебхук повторяется 3 раза с интервалом 5 секунд. Этот механизм используется в remnawave-tg-shop.

## Решение
Напоминания планирует и отправляет магазин. Для каждой подписки хранится момент отправки каждого напоминания (дата окончания минус смещение). Раз в минуту отправляются все напоминания, которые пора отправить и которые ещё не отправлены. Пропущенные при недоступности магазина досылаются; из нескольких наступивших отправляется самое позднее. Изменение даты окончания пересчитывает будущие напоминания. Перед отправкой дата окончания сверяется с панелью. Расписание настраивается в админке, у триала — своё. Отсчёт — ровно N часов, без подстройки под часовые пояса.

## Альтернативы
Уведомления панели — отклонено:
- событие привязано к одной минуте и не восстанавливается; при перезапуске панели или недоступности магазина дольше ~15 секунд напоминание молча теряется, в том числе при каждом обновлении магазина;
- одно расписание на все подписки, включая триал;
- настройка в `.env` панели с перезапуском, а не в админке.

Плюсы, от которых мы отказываемся: не нужно писать планировщик; дата окончания берётся напрямую из источника истины (у нас это компенсируется сверкой перед отправкой).

## Последствия
- В магазине есть планировщик напоминаний.
- Магазин хранит факт отправки каждого напоминания за текущий срок подписки.
- Уведомления об истечении в панели оператору включать не нужно.
