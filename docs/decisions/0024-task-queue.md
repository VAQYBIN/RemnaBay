# 0024. Своя очередь фоновых задач на PostgreSQL

- **Дата:** 2026-10-03
- **Статус:** принято

## Контекст
Очередь задач — основа обещания надёжности. Проведён эксперимент ([research/spike-task-queue.md](../research/spike-task-queue.md)): Procrastinate против своей минимальной очереди, по семи одинаковым вопросам.

## Решение
Своя очередь на PostgreSQL через SQLAlchemy, доступная остальному коду только через собственный интерфейс магазина («поставить задачу», «выполнить задачу»).

До переноса в проект в неё добавляются:
- **таймаут задачи** меньше таймаута простоя транзакции в PostgreSQL и проверка их соотношения;
- **счёт попытки до выполнения** отдельной короткой транзакцией — задача, которая раз за разом обрывает выполнение, доходит до лимита и становится проваленной;
- **история попыток** с текстом ошибок (нужна для карточки проблемного платежа, 4.21);
- **поочерёдная постановка задач одной подписки** (блокировка подписки при постановке) — иначе порядок номеров может разойтись с порядком коммитов;
- **ожидание после окончательного провала:** следующие задачи подписки не выполняются, пока команда не разберёт проваленную (4.27);
- **очистка старых завершённых задач.**

Правила для задач:
- задача сверяет состояние перед внешним действием (4.15) — «оживший» после зависания воркер может доделать устаревшую попытку;
- большая работа делится на много небольших задач (4.28), чтобы транзакции оставались короткими.

## Альтернативы
- Procrastinate — отклонено. Задача упавшего воркера по умолчанию навсегда остаётся «в работе» и блокирует операции подписки; повторы по времени, текст ошибки и оживление зависших задач — свой код поверх библиотеки; ключевая логика — в PL/pgSQL библиотеки; проект ищет мейнтейнеров.
- Очереди на Redis — отклонено ранее: лишний сервис и окно между записью в базу и постановкой задачи.

## Последствия
- Очередь — около полутора-двух сотен строк собственного кода; ошибки в них — наша ответственность, поэтому модуль покрывается тестами по сценариям эксперимента.
- Если окажется много долгих задач, выбор пересматривается; замена не затронет сценарии.

## Уточнение
См. [решение 0036](0036-admin-misc-refinements.md): запрос к панели внутри задачи — с коротким таймаутом (порядка 10 секунд); «занятость» подписки для соблюдения порядка держится на отдельной служебной отметке, а не на строке подписки, чтобы показ подписки клиенту и в админке никогда не ждал.
