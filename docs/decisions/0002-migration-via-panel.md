# 0002. Миграция через панель и промежуточный формат

- **Дата:** 2026-09-30
- **Статус:** принято

## Контекст
Целевой пользователь уже продаёт VPN и переезжает с другого бота или с «голой» панели. Без переноса клиентов переезд невозможен. Источников много, и поддерживать каждый отдельно дорого.

## Решение
Три слоя: усыновление пользователей панели (универсально), адаптеры источников в единый промежуточный формат, обязательный пробный прогон перед импортом. В v1 — «голая» панель, семейство remnawave-tg-shop и Bedolaga.

## Альтернативы
Прямой импорт из каждой чужой БД — отклонено: N импортеров с N наборами правил, не расширяется силами сообщества.

## Последствия
Промежуточный формат нужно спроектировать и задокументировать как публичный контракт.

## Уточнение
Нарезкой ([06-scope.md](../06-scope.md)) «голая» панель и семейство remnawave-tg-shop отнесены к MVP, Bedolaga — к v1.
