# 0053. Вход в админку через Telegram OpenID Connect

- **Дата:** 2026-10-06
- **Статус:** принято

## Контекст
На этапе 4 вход в админку сделан по [решению 0051](0051-stage-4-refinements.md): кнопка на странице входа даёт ссылку на бот, бот присылает подтверждение с кодом, браузер опросом получает сессию; на `/admin` бот присылает кнопку `login_url`. Владелец захотел вход через Telegram OpenID Connect — стандартный «Войти через Telegram», который Telegram запустил в 2026 году. Исследование и эксперимент на тестовом боте — [research/telegram-oidc.md](../research/telegram-oidc.md).

## Решение
- **Главный вход — Telegram OpenID Connect.** Кнопка «Войти через Telegram» ведёт на страницу Telegram. Участник подтверждает вход в приложении Telegram и возвращается в админку с открытой сессией. Поток — Authorization Code с PKCE (S256). Код обменивается на токены на сервере магазина с Client Secret. ID token проверяется:
  - подпись — по ключам Telegram (RS256 или ES256);
  - издатель — `https://oauth.telegram.org`;
  - получатель — ID бота магазина;
  - срок действия и `nonce`.
  Участник определяется по claim `id` (Telegram ID), а не по `sub`.
- **Запасной вход — через бот с кодом подтверждения** (как в 0051). Менее заметной ссылкой на странице входа: если у Telegram сломается вход по OIDC, команда не останется без админки. Он же работает при разработке без публичного адреса.
- **`/admin`** — участнику команды бот присылает обычную ссылку на страницу входа (кнопка-ссылка), а не `login_url`. Вход по `login_url` убирается: он требует `/setdomain` и данных старого виджета.
- **Client Secret** — новый обязательный параметр `.env` `TELEGRAM_LOGIN_CLIENT_SECRET` (1.1): без него не войти в админку, поэтому в настройках админки ему не место. Client ID — ID бота из `BOT_TOKEN`.
- **Попытка входа** хранится в зашифрованной cookie браузера: `state`, `nonce`, `code_verifier`. Она одноразовая и действует столько же, сколько подтверждение входа (1.5). Без cookie и при чужом `state` вход отклоняется. Если сессия уже открыта — например, браузер открыл адрес возврата повторно, — ведём в админку.
- **Оператор настраивает бота в @BotFather** (документация оператора, этап 11):
  - Login Widget → OpenID Connect; переключение необратимо;
  - Redirect URI `https://<домен>/api/admin/auth/telegram/callback`;
  - Trusted Origin `https://<домен>`;
  - подпись RS256;
  - Client Secret — в `.env`;
  - имя и аватар бота — бренд магазина: их участник видит на странице Telegram.

## Альтернативы
- **Только OIDC, без запасного входа** — отклонено: сбой входа у Telegram закрыл бы команде админку, а при разработке без публичного адреса войти было бы нельзя.
- **Оставить `login_url` на `/admin`** — отклонено: второй механизм проверки (`/setdomain`, данные старого виджета) ради входа в одно нажатие; ссылка на страницу входа с OIDC даёт то же в два нажатия.
- **Убрать `/admin`** — отклонено: из бота быстрее всего попасть в админку с телефона.
- **Попытку входа хранить в базе** — отклонено: зашифрованная cookie держит ту же одноразовость и срок без новой таблицы, и попытка привязана к браузеру, который начал вход.
- **Authlib для OIDC** — отклонено: крупная зависимость ради одного провайдера; проверка ID token — несколько функций на `cryptography`, которая уже есть (0046).
