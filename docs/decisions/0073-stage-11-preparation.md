# 0073. Подготовка этапа 11: перезапуск, образы, версии, пароль базы, документация, тестовые серверы

- **Дата:** 2026-10-20
- **Статус:** принято

## Контекст
Этап 11 плана — развёртывание ([решение 0026](0026-deployment.md)). Перед кодом остались вопросы, на которые спека не отвечала: как перезапускать процесс, который перестал работать, где публиковать образы, как нумеровать версии и выпускать их, как оператор задаёт пароль встроенной базы, где лежит документация для операторов и на каких серверах проверяется MVP ([решение 0031](0031-stages-refined.md)). Тогда же закрыты два вопроса из `open-questions.md`, решения по которым уже работали в коде как предложения.

## Решение
1. **Перезапуск.** Docker Compose перезапускает только упавший контейнер; контейнер в состоянии unhealthy он не трогает.
   - Веб, воркер и база — `restart: unless-stopped`: поднимаются после падения и перезагрузки сервера, но не после того, как оператор остановил их сам.
   - Процессы сами завершаются с ошибкой, когда потеряли работоспособность (например, воркер долго не может связаться с базой или у него остановился цикл задач), — политика перезапуска поднимает их заново.
   - Шаг миграций — без перезапуска (`restart: "no"`): он одноразовый.
   - Проверки здоровья остаются: зависший процесс, который не может завершиться сам, виден в `docker ps` как unhealthy.
2. **Образы** публикуются в GitHub Container Registry: `ghcr.io/vaqybin/remnabay`, для amd64 и arm64, с номером версии, без опоры на `latest`.
3. **Версии и выпуск.**
   - Семантическое версионирование: MVP — `0.1.0`, v1 — `1.0.0`; исправления после проверки на тестовом сервере — `0.1.1` и дальше.
   - Выпуск: владелец сливает `dev` в `main` и ставит тег `v<версия>`; CI по тегу собирает и публикует образ для обеих архитектур.
   - **Предварительные версии для проверки на тестовых серверах:** тег `v<версия>-rc.<N>` (например, `v0.1.0-rc.1`) ставится на ветку этапа; CI публикует образ с тем же номером. Тестовые серверы ставят rc; ошибки, найденные на проверке, исправляются следующим rc. Когда проверки пройдены, владелец сливает `dev` в `main` и ставит тег выпуска.
   - Changelog — `CHANGELOG.md` на русском, раздел на каждую версию.
4. **Пароль встроенной базы.**
   - Для PostgreSQL из compose оператор задаёт в `.env` только `POSTGRES_PASSWORD`; адрес подключения compose собирает сам. `DATABASE_URL` оператор задаёт, только если база на другом сервере.
   - В документации — готовая команда, которая создаёт пароль и записывает его в `.env`: `openssl rand -hex 64` и `sed`.
   - PostgreSQL берёт пароль только при первом запуске базы: смена `POSTGRES_PASSWORD` потом пароль не меняет. В документации — предупреждение и рецепт смены пароля.
5. **Документация для операторов** — в `deploy/`: README с установкой, обновлением и резервным копированием, рядом — файлы вариантов прокси. В корневом README — короткий раздел «Установка» со ссылкой. Язык — русский ([решение 0041](0041-public-docs-language.md)).
6. **Проверка MVP на двух серверах:**
   - первый — сервер с панелью: Nginx панели, общая Docker-сеть, вебхук панели — по внутренней сети; amd64, панель 3.4.4;
   - второй — отдельный сервер без настроенного прокси: вебхук панели — через публичный адрес; проверяются оба варианта чистого сервера — свой Nginx с certbot и Caddy.
   - Разворачивает владелец по документации этапа — так проверяется и документация.
7. **Отключение провайдера, пока есть неоплаченные счета.** Перед отключением админка предупреждает, сколько счетов ещё может быть оплачено, и советует не отключать провайдера до истечения окна опроса (время жизни счёта плюс 24 часа) — иначе поздняя оплата не применится сама, пока ключи не введут снова.
8. **`{brand_name}`, пока название бренда не задано,** — подставляется имя бота в Telegram (так сделано на этапе 4).

## Альтернативы
- **`restart: always`** — отклонено: после перезагрузки сервера поднимает и магазин, который оператор остановил сам, например на время восстановления базы из копии.
- **Отдельный сервис-перезапускатель unhealthy-контейнеров** — отклонено: лишний сервис у каждого оператора и доступ к сокету Docker, то есть полный контроль над сервером, на котором работает панель.
- **Docker Hub** — отклонено: отдельный аккаунт и токен; GHCR рядом с репозиторием и бесплатен для публичного проекта.
- **Пароль базы и в `POSTGRES_PASSWORD`, и в `DATABASE_URL`** — отклонено: оператор пишет его дважды и должен следить, чтобы совпадало.
- **Документация для операторов в `docs/`** — отклонено: там спека, оператору в ней не разобраться.
