# 0030. Чеки — отдельный модуль, в v1

- **Дата:** 2026-10-04
- **Статус:** принято

## Контекст
Продавец обязан выдавать чеки. Автор — самозанятый: ЮКасса убрала отправку чеков для самозанятых, поэтому в текущем магазине автора чеки формируются через «Мой налог» (библиотека nalogo). Для ИП и ООО есть чеки ЮКассы, но автору они неактуальны.

## Решение
- В MVP чеков нет: MVP проверяется на тестовом сервере.
- В v1 — **модуль чеков со своим контрактом,** по аналогии с контрактом платёжного провайдера: «выдать чек на применённый платёж», «аннулировать чек при возврате».
- Первая реализация — **«Мой налог» для самозанятых.**
- Чеки ЮКассы для ИП и ООО — новая реализация модуля, по запросу сообщества.

## Альтернативы
- Чеки ЮКассы в MVP — отклонено: автор ими не пользуется, а для самозанятых они недоступны.

## Последствия
- Чек физлицу в «Моём налоге» не требует контакта покупателя — бот по-прежнему не спрашивает лишнего.
- Интеграции с «Моим налогом» работают через неофициальный API; модуль должен переживать его изменения: неудачная выдача чека не мешает применению платежа, а становится видимой команде.
- Сценарии и критерии модуля проектируются при подготовке v1.
