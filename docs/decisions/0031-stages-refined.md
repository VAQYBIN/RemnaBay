# 0031. Уточнение этапов: MVP — проверка, v1 — переезд автора

- **Дата:** 2026-10-04
- **Статус:** принято; уточняет [решение 0015](0015-mvp-definition.md)

## Контекст
Решение 0015 определило MVP как минимум, с которым автор переводит свой магазин. На деле автор планирует переезжать только с v1, когда продукт будет полноценным, а MVP — развернуть на тестовом сервере и проверить.

## Решение
- **MVP** — первая рабочая версия: автор разворачивает её на тестовом сервере и проверяет на реальной панели.
- **v1** — версия, на которую автор полностью переводит свой магазин; одновременно публичный релиз.
- Нарезка фич MVP не меняется: это рабочее ядро, которое имеет смысл проверить первым.
- В v1 должно войти всё, без чего автор не готов переезжать. Уже там: бот поддержки, модуль чеков. При планировании v1 решаются блокировка клиентов, автопродление и другие возможности текущего магазина автора.
- Принцип «данные с первого дня» из решения 0015 действует.

## Последствия
- Проверка MVP на тестовом сервере — источник поправок к спеке перед v1.
