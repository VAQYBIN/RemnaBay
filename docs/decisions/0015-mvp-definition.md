# 0015. Определение MVP и данные с первого дня

- **Дата:** 2026-10-01
- **Статус:** определение этапов уточнено [решением 0031](0031-stages-refined.md); принцип «данные с первого дня» действует

## Контекст
Спецификация описывает продукт целиком. Без границы первой версии разработка растянется на месяцы, а «готово» останется ощущением. Кроме того, открытым оставался вопрос о месте собственного магазина автора.

## Решение
- **MVP** — минимум, с которым автор переводит на проект свой действующий магазин. Магазин автора — первый пользователь продукта, а не сам продукт: продвинутые нужды автора сверх MVP идут через v1 или расширения.
- **v1** — минимум для публичного релиза.
- **Потом** — всё остальное.
- **Данные с первого дня:** модель предметной области реализуется в MVP целиком, откладываются только функции и экраны.

## Альтернативы
- MVP как «минимум для сообщества» — отклонено: граница размыта, её нельзя проверить.
- Откладывать вместе с функциями и данные — отклонено: отложенные функции потом не на что опереть (стоимость отрезков, реестр устройств).

## Последствия
- Экраны и настройки проектируются в первую очередь для MVP.
- Нарезка проверяется просто: сможет ли автор перевести свой магазин.
