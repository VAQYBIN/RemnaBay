# 3. Экраны бота и веб-админки

**Статус:** ✅ утверждён

Экраны описываются для MVP. Формат бота — [решение 0017](decisions/0017-bot-format.md); возможности Telegram — [research/telegram-bot-api.md](research/telegram-bot-api.md).

## Принципы бота
- **Меню живёт в одном сообщении,** которое редактируется при нажатии кнопок.
- **События — отдельные сообщения:** оплата, ссылка на подписку, инструкция, напоминания, уведомления. Их не перезаписывает следующее нажатие.
- **Инструкция по подключению берётся из Subscription Page панели** ([решение 0019](decisions/0019-subpage-guide.md)): оператор правит её в одном месте — в панели.
- **Rich-сообщения — только там, где структура помогает:** инструкция по подключению, выбор тарифа, карточка подписки. Остальное — обычные сообщения.
- **Оператор правит поля, а не разметку.** Структуру rich-сообщений собирает магазин; оператор в админке редактирует тексты и значения полей.
- **Даты показываются через сущность date_time,** чтобы клиент видел их в привычном формате и в своём часовом поясе. Запасной текст даты — дата и время в часовом поясе магазина с подписью пояса, например «1 ноября 2026, 23:00 (МСК)»: его видят клиенты, которые date_time не форматируют (Android внутри rich, старые версии) ([решение 0044](decisions/0044-rich-messages-refinements.md)).
- **Цвет кнопок несёт смысл:** зелёный (success) — целевое действие экрана («Оплатить», «Продлить», «Попробовать бесплатно»); красный (danger) — разрушительное («Удалить устройство»); без цвета — навигация. Не больше одной зелёной кнопки на экране.
- **Недоступное действие показывается неактивной кнопкой,** если клиенту полезно знать, что оно существует; иначе не показывается.
- **Ссылка на подписку всегда копируется кнопкой.**
- **На каждом событии есть кнопка «Главное меню».**
- Иконки-эмодзи на кнопках — только если оператор их задал (требуют Telegram Premium у владельца бота).

## Команды
- `/start` — главное меню (с параметром — реферальная ссылка, в том числе старого бота).
- `/help` — инструкция по подключению и контакт поддержки.
- `/admin` — скрытая, не показывается в меню: участнику команды бот присылает кнопку со ссылкой на страницу входа в админку (1.4).

## Карта

```
/start
├── [магазин не открыт] → З0 «Магазин скоро откроется»
└── З1 Главное меню
    ├── «Попробовать бесплатно» ──→ С3 Триал активирован
    ├── «Купить подписку» ────────→ З4 Выбор тарифа → З5 Подтверждение → З6 Оплата
    │     (в том числе при единственной триальной подписке — 3.36)
    ├── «Моя подписка» ───────────→ З3 Карточка подписки
    ├── «Мои подписки» ───────────→ З2 Список подписок → З3 Карточка подписки
    ├── «Ввести промокод» ────────→ З8 Ввод промокода
    └── «Поддержка» ──────────────→ ссылка на контакт оператора

З3 Карточка подписки
├── «Продлить» ─────────────→ З4 Выбор тарифа / З5 Подтверждение
├── «Скопировать ссылку»     (копирует в буфер)
├── «Как подключить» ───────→ С2 Инструкция по подключению
├── «Устройства» ───────────→ З7 Устройства
└── «Назад»

З6 Оплата ──(провайдер)──→ С1 Подписка готова / С4 Оплата получена, подписка создаётся / С5 Оплата отклонена
```

## Экраны (меню, редактируются на месте)

### З0. Магазин скоро откроется
Ответ на любое сообщение, пока владелец не открыл магазин (1.13). Участники команды и тестировщики (1.21) видят обычный бот.

### З0а. Магазин временно закрыт
Когда владелец закрыл открытый магазин (1.22): покупка, продление и триал отвечают «Магазин временно закрыт»; подписки, ссылки и инструкции доступны.

### З1. Главное меню
- **Шапка:** приветствие бренда. Если подписки есть — краткая сводка по каждой: название, статус, дата окончания.
- **Кнопки по состоянию клиента:**
  - нет подписок, триал доступен — «Попробовать бесплатно» (зелёная), «Купить подписку»;
  - нет подписок, триал недоступен — «Купить подписку» (зелёная);
  - одна подписка — «Моя подписка»; несколько — «Мои подписки»;
  - единственная подписка — триальная — дополнительно «Купить подписку» (зелёная), 3.36;
  - всегда — «Ввести промокод»; «Поддержка» — если оператор задал контакт поддержки.
- **Варианты шапки:** новый клиент; клиент с подписками; усыновлённый клиент при первом открытии («Ваши подписки найдены, ссылки прежние»).

### З2. Список подписок
Только если подписок больше одной (3.24). Кнопка на каждую подписку с названием и статусом.

### З3. Карточка подписки — rich
- **Содержимое:** название, тариф, статус, дата окончания, устройства «занято X из Y» (если в панели включён лимит устройств), пометка, если тариф в архиве.
- **Кнопки:** «Продлить» (зелёная) — для триальной подписки вместо неё «Купить подписку» (3.36), для отключённой в панели её нет, в том числе у триальной — вместо неё «обратитесь в поддержку» (3.36, 4.7); «Скопировать ссылку»; «Как подключить»; «Устройства» (если включён лимит устройств); «Назад».
- **Состояния:** активна; истекла (кнопка «Продлить» ведёт к выбору тарифа, если тариф в архиве — 3.21); отключена в панели («обратитесь в поддержку», 4.7); данные могут быть неактуальны (панель недоступна, 4.12).

### З4. Выбор тарифа — rich
- **Содержимое:** тарифы в продаже в порядке, заданном владельцем (2.4): название, срок, цена, лимит устройств, описание.
- **Кнопки:** по одной на тариф; «Попробовать бесплатно» — внизу, если триал клиенту доступен (5.2); «Назад».
- **Варианты шапки:** покупка; продление истёкшей подписки на архивном тарифе («ваш тариф больше не продаётся, выберите новый»); продление подписки без тарифа (3.35).
- При продлении активной подписки этот экран пропускается — сразу З5 с текущим тарифом (3.20).

### З5. Подтверждение
- **Содержимое:** тариф, срок, цена, скидка по промокоду (если введён), итог; при продлении — новая дата окончания.
- **Кнопки:** «Оплатить» (зелёная); «Ввести промокод»; «Назад».
- При итоге 0 (скидка 100%) кнопка — «Получить» (8.8).

### З6. Оплата
- **Содержимое:** сумма, до какого времени действует счёт.
- **Кнопки:** «Перейти к оплате» (ссылка на страницу провайдера); «Отменить» — платёж переходит в «отменён» (3.38).
- Провайдер недоступен — сообщение «Оплата временно недоступна, попробуйте позже» вместо экрана (3.30).

### З7. Устройства
- **Содержимое:** устройства подписки (платформа, модель, приложение, дата подключения), «занято X из Y».
- **Кнопки:** «Удалить» у каждого устройства (красная); «Удалить все» (красная, с подтверждением — 6.5); «Назад».
- **Состояния:** нет устройств; удаление поставлено в очередь, потому что панель недоступна (6.6).

### З8. Ввод промокода
- Бот просит прислать код (с force_reply).
- **Результаты:** скидка применена (возврат к З5); дни добавлены (выбор подписки, если их несколько — 8.10); ошибка с причиной (8.12); ввод временно ограничен (8.13).
- Код на дни, введённый с экрана З5, — подсказка, что он активируется из главного меню (8.9).

## Не в MVP
Экран приглашения друзей, переименование подписки, покупка ещё одной подписки, смена тарифа для активной подписки, отключение рассылок, привязка по ссылке подписки — появятся вместе с соответствующими фичами v1.

Экран «Пригласить друга» появляется в v1 вместе с наградами. В MVP реферальные ссылки (включая ссылки старого бота) распознаются и связи записываются, но экрана нет: показывать личную ссылку без награды странно.

## Страница-переходник
Веб-страница магазина, через которую открываются диплинки приложений: Telegram не открывает нестандартные схемы (`happ://` и подобные) из кнопок ([решение 0019](decisions/0019-subpage-guide.md)).
- Автоматически открывает приложение; если не сработало — кнопка «Открыть {app_name}».
- Ниже — «Приложение не установлено?» и ссылки на установку из конфига Subscription Page.
- Учитывает язык клиента и светлую или тёмную тему устройства; если тема устройства неизвестна — тёмная.
- **Только бренд оператора:** знак (или горизонтальный логотип), название, фирменный цвет. Упоминания RemnaBay нет ([решение 0038](decisions/0038-branding.md)).

## Экраны веб-админки

### Принципы админки
- **Разделы соответствуют сущностям и сценариям**, а не техническим модулям.
- **Действие доступно там, где на него смотрят:** вернуть деньги — из карточки платежа, выдать дни — из карточки клиента.
- **Опасные действия требуют подтверждения** с описанием последствий (возврат, архивация последнего тарифа, удаление всех устройств, применение импорта).
- **Права по таблице из [01-domain.md](01-domain.md):** недоступные роли действия не показываются.
- **Изменения настроек применяются без перезапуска.**
- **Бренд оператора на раме RemnaBay** ([решение 0038](decisions/0038-branding.md)): админка и экран входа показывают название, логотип и фирменный цвет оператора; RemnaBay упоминается только в «О программе». Тема следует устройству, если она неизвестна — тёмная; переключатель «Системная / Светлая / Тёмная» — в меню участника. Направление оформления — [design/DESIGN.md](design/DESIGN.md).

- **Админка удобна на телефоне.** Владелец, который работает один, в MVP не имеет быстрых действий в боте (они в v1) — значит, «клиент написал, что не работает» он будет разбирать с телефона через веб-админку. Основные сценарии — поиск клиента, карточка, выдача дней, «Требуют внимания» — должны быть удобны на узком экране; настройки и импорт допустимо делать с компьютера.

### Навигация
```
Вход
Главная
Клиенты ─── Карточка клиента
Платежи ─── Требуют внимания
         └─ Карточка платежа
Тарифы
Промокоды
Рассылки
Миграция
Журнал
О программе
Настройки ── Бренд
          ├─ Тексты бота
          ├─ Оплата
          ├─ Триал
          ├─ Напоминания
          ├─ Магазин
          ├─ Подписки
          ├─ Промокоды
          ├─ Панель
          └─ Вход в админку
```

### А0. Вход
Кнопка «Войти через Telegram»: вход подтверждается в Telegram (OpenID Connect), отказ для чужого аккаунта (1.4–1.6). Запасная ссылка «Войти через бот»: бот присылает подтверждение с кодом, страница ждёт подтверждения. На команду `/admin` бот присылает ссылку на эту страницу ([решение 0053](decisions/0053-telegram-oidc-login.md)).
- Оформлен брендом оператора: логотип, название, фирменный цвет (1.23).
- Пока название и знак не заданы (первый вход), экран входа и шапка админки показывают название и знак RemnaBay — так же, как фирменный цвет по умолчанию.

### А1. Главная
- **Пока магазин не открыт** — чек-лист с кнопкой «Открыть магазин» (1.7–1.15).
- **«Требуют внимания»** — счётчик и переход к списку (4.20); отдельной строкой — «ждут панель: N» (4.30).
- **Состояние связей:** панель доступна или нет, когда пришло последнее событие от панели, когда была последняя сверка; предупреждение, если в панели выключен лимит устройств.
- Невыполненные пункты чек-листа остаются на главной и после открытия.

- **Ключевые цифры для владельца (1.17–1.20):** активные подписки, новые клиенты и выручка за период, подписки, истекающие в ближайшие 3 дня.

### А2. Клиенты
- Строка поиска по Telegram ID, username, имени, ссылке подписки, имени пользователя в панели (10.1).
- Список: имя, username, число подписок, ближайшая дата окончания, пометки («бот заблокирован», «усыновлён»).

### А3. Карточка клиента
- **Шапка:** имя, username, Telegram ID, пометки, дата появления.
- **Подписки:** для каждой — тариф, статус, дата окончания, устройства; действия «Выдать дни», «Сбросить устройства», «Синхронизировать с панелью».
- **Платежи** клиента со статусами; переход в карточку платежа.
- **Триал, реферальные связи** (кто пригласил, кого пригласил).
- **Запросы на возврат** и кнопка «Зафиксировать запрос».
- **Журнал по клиенту.**
- Выдача дней — форма: подписка, число дней, обязательный комментарий (10.3).

### А4. Платежи
- Список с фильтрами по состоянию (ожидает оплаты, оплачен, применён, отклонён, истёк, отменён, оплачен — не применён, решён вручную, возвращён, частично возвращён; отдельно — неизвестные) и периоду.
- Вкладка **«Требуют внимания»** (4.20, 4.23, 4.30, 4.31): проваленные платежи и другие операции, операции, ждущие панель, неизвестные платежи. Для операций, которые не являются платежами, — «Повторить» и «Отменить» с комментарием (4.32).

### А5. Карточка платежа
- Клиент, подписка, тариф, сумма, промокод, статус, история попыток с текстом ошибок (4.21).
- Действия по ситуации: «Применить повторно», «Применить созданием новой подписки», «Отметить решённым вручную» (с комментарием) — 4.22; для неизвестного платежа — «Привязать к клиенту» с выбором, что применить (4.23); «Вернуть» — только владелец, один раз на платёж (10.8–10.12).
- Экран возврата: предложенная сумма, способ, новая дата окончания подписки, подтверждение.

### А6. Тарифы
- Список в порядке показа клиентам, с перетаскиванием (2.4); разделение «в продаже» и «в архиве».
- Форма тарифа: название, описание, срок, цена, лимит устройств, сквады из панели (2.1–2.2).
- Действия: архивировать / вернуть в продажу, удалить (если подписок не было) — 2.7–2.9.

### А7. Промокоды
- Список: код, вид, значение, активации, срок, состояние.
- Форма: код (ввести или сгенерировать), вид, значение, ограничения (8.1–8.2); отключение (8.3).

### А8. Рассылки
- История с итогами (11.8).
- Создание: текст с предпросмотром, изображение, кнопки, сегмент с числом получателей, «Отправить себе», подтверждение (11.1–11.4).
- Идущая рассылка: прогресс и кнопка «Остановить» (11.5–11.7).

### А9. Миграция
- **Усыновление:** запуск пробного прогона, отчёт, «Применить», итоговый отчёт (9.1–9.7).
- **Импорт:** загрузка файла в промежуточном формате, пробный прогон, отчёт с конфликтами, применение (9.10–9.12).
- История прогонов.

### А10. Журнал
Все записи с фильтрами: кто (участник команды, клиент, система, панель, провайдер), что, над чем, период, результат. Только чтение (4.26).
