# 5. Миграция

**Статус:** 🟡 стратегия утверждена, детали не проработаны

## Ключевая идея
Все боты для продажи работают поверх одной панели Remnawave. Сама подписка (срок, трафик, сквады, ссылка) живёт в панели и не теряется при смене бота. Переносить нужно только данные, которые хранит сам бот: балансы, рефералов, историю платежей, промокоды, факт использования триала.

## Три слоя
### 1. Усыновление пользователей панели
Универсальная база, работает для любого источника, включая «без бота». Магазин подхватывает существующих пользователей панели и привязывает их к Telegram-аккаунтам. Клиент открывает новый бот и видит свою подписку. Даже без адаптеров оператор не теряет ни одного клиента.

### 2. Адаптеры источников
Каждый адаптер переводит данные конкретного бота в **один документированный промежуточный формат**. Импорт умеет работать только с этим форматом. Формат открыт: адаптер к нему — точка расширения и хороший первый вклад для контрибьютора.

### 3. Пробный прогон
Перед применением импорт показывает отчёт: сколько пользователей перенесётся, у кого нет Telegram ID, где дубли, какие балансы и рефералы подтянутся, что не распознано. Без отчёта оператор не должен иметь возможности запустить импорт.

## Стоимость перенесённых дней
Дни, перенесённые при миграции, — отрезки нулевой стоимости: магазин не видел платежей за них. При смене тарифа в первый период после переезда их неиспользованная стоимость равна нулю. Погрешность разовая: со следующего продления стоимость считается по платежам магазина. При желании оператор компенсирует её, начислив клиентам бонусы.

## Тот же бот или новый
Оператор может переехать на тот же Telegram-бот (тот же токен) или на новый. На том же боте клиенты уже открывали чат, и магазин может сразу сообщить им о переезде. На новом — нет: Telegram не позволяет боту писать первым.

## Реферальные коды
Старые реферальные ссылки продолжают ходить по чатам и соцсетям, а формат параметра у каждого бота свой. Адаптер переносит реферальные коды, и магазин распознаёт ссылки старого бота.
