# Промежуточный формат миграции

**Статус:** ✅ утверждён как контракт версии 1; поля уточняются при реализации адаптера — с повышением версии формата.

Публичный контракт между адаптерами чужих ботов и импортом магазина ([решение 0002](decisions/0002-migration-via-panel.md), критерии 9.8–9.17). Любой может написать адаптер для своего бота: достаточно выдать файл в этом формате.

## Общее
- Один файл JSON в кодировке UTF-8.
- Поле `format_version` — номер версии формата. Импорт отказывается принимать неизвестную версию и сообщает, какие поддерживает.
- Поле `source` — откуда данные: название бота и версия, если известна.
- Обязательные поля отмечены «да»; необязательные адаптер может опустить, если в источнике их нет.

## Клиент
| Поле | Обязательно | Значение |
|---|---|---|
| Telegram ID | да | Идентификатор клиента |
| username | нет | Без «@» |
| Имя | нет | Как в старом боте |
| Язык | нет | Код языка клиента |
| Дата появления | нет | Когда клиент впервые открыл старый бот |
| Триал использован | нет | Да или нет; если поле отсутствует — считается «нет» |
| Платил в старом боте | нет | Да или нет. Нужно для промокодов «только для клиентов без оплат» (8.2): «нет» — клиент считается новым. Если поле отсутствует, усыновлённый клиент считается платившим, а клиент без пользователя в панели — без оплат ([решение 0070](decisions/0070-migrated-paid-clients.md)) |
| Пользователи панели | нет | Список: числовой ID, короткий идентификатор (`shortUuid`) и/или имя (`username`) пользователя панели; хватает любого одного ([решение 0043](decisions/0043-panel-checks-refinements.md)) |
| Реферальные коды | нет | Коды старого бота, ведущие на этого клиента |
| Пригласивший | нет | Telegram ID клиента, который пригласил этого |

## Сопоставление тарифов (необязательно)
Если в старом боте есть тарифы, адаптер может передать подсказку: какой тариф старого бота был у пользователя панели. Импорт показывает подсказку в пробном прогоне; окончательное сопоставление с тарифами магазина задаёт оператор (9.15).

## Ключи JSON и пример
> **Предложение (не утверждено), [решение 0071](decisions/0071-stage-10-preparation.md):** ключи и правила ниже реализованы в версии 1 на этапе 10.

| Поле | Ключ | Тип |
|---|---|---|
| Версия формата | `format_version` | число, сейчас `1` |
| Источник | `source.name`, `source.version` | строки; `version` необязательна |
| Клиенты | `clients` | список |
| Telegram ID | `telegram_id` | целое больше нуля |
| username | `username` | строка без «@» |
| Имя | `name` | строка |
| Язык | `language` | код языка: `ru`, `en`, `pt-br` |
| Дата появления | `first_seen_at` | дата и время ISO 8601 с часовым поясом |
| Триал использован | `trial_used` | `true` или `false` |
| Платил в старом боте | `paid_in_old_bot` | `true`, `false` или поле отсутствует |
| Пользователи панели | `panel_users` | список объектов: `id` (число), `short_uuid`, `username`; нужен хотя бы один из трёх. Необязательный `tariff_hint` — название тарифа старого бота (подсказка для сопоставления) |
| Реферальные коды | `referral_codes` | список строк — значение параметра `start` ссылки старого бота целиком, например `ref_uAB12CD34E` |
| Пригласивший | `invited_by` | Telegram ID |

- Неизвестные ключи импорт пропускает: новая необязательная версия поля не ломает старый импорт.
- Telegram ID, который встречается в файле дважды, импорт не переносит ни разу и показывает в «не распознано».
- Язык, на который у магазина нет перевода, не сохраняется: клиент получает язык по умолчанию.

```json
{
  "format_version": 1,
  "source": {"name": "remnawave-tg-shop", "version": "схема форка"},
  "clients": [
    {
      "telegram_id": 100000001,
      "username": "ivan",
      "name": "Иван",
      "language": "ru",
      "first_seen_at": "2025-03-01T12:00:00+00:00",
      "trial_used": true,
      "paid_in_old_bot": true,
      "panel_users": [{"id": 42, "username": "tg_100000001"}],
      "referral_codes": ["ref_uAB12CD34E", "ref_AB12CD34E", "ref_100000001"],
      "invited_by": 100000002
    }
  ]
}
```

## Чего в формате нет и почему
- **Платежи старого бота** — магазин их не видел; стоимость перенесённых дней равна нулю ([решение 0012](decisions/0012-tariff-change.md)). Переносится только факт: платил ли клиент («Платил в старом боте»).
- **Балансы и бонусы** — бонусного счёта в MVP нет; оператор при желании начислит бонусы сам (v1).
- **Срок, трафик, устройства** — живут в панели и берутся оттуда.
